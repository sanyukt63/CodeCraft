# Learning Accessibility Checklist

- Keep heading levels in a logical order.
- Ensure interactive tasks work with a keyboard.
- Do not rely on color alone for correct or incorrect states.
- Provide readable code examples on narrow screens.
- Give controls accessible names.
- Keep feedback messages clear and close to the relevant activity.

## Keyboard and focus review

For each interactive learning flow, verify that:
- Every action is reachable with the keyboard.
- Focus order follows the visual reading order.
- Focus indicators remain visible against the page background.
- Dialogs return focus to the control that opened them when closed.
- Validation errors are announced and associated with the relevant field.

Repeat these checks at narrow viewport widths and after layout changes.
