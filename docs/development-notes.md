# Development Notes

## Working approach

1. Understand the existing implementation before changing it.
2. Keep features modular and avoid unrelated refactors.
3. Update documentation when behavior or setup changes.
4. Run the relevant checks before committing.

## Review checklist

- [ ] Change solves the intended problem
- [ ] Existing behavior is preserved where expected
- [ ] Error cases are handled
- [ ] Documentation is updated when needed
- [ ] No unnecessary generated or local files are committed
